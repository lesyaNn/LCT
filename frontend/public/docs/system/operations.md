**Для системного администратора.** Пользовательские действия описаны в других разделах справочного центра. В репозитории есть технические заметки о прошлых этапах работы. Перед применением сверяйте их с текущими `docker-compose.yml` и скриптами: `docs/INSTALL.md`, `docs/SECURITY.md`, `docs/DEMO_SEED.md` и `docs/ARCHITECTURE.md`.

## Запуск и проверка

Скопируйте `.env.example` в `.env`, задайте безопасные пароли и запустите `docker compose up -d --build`. Проверяйте здоровье сервисов через `./scripts/wait-healthy.sh`. Миграции backend выполняет при старте; их статус можно посмотреть командой `docker compose exec -T backend python scripts/migrate.py status`.

## Демо-стенд

`./scripts/demo-setup.sh` поднимает локальный стек, загружает данные и назначает demo-пользователям область доступа. Флаг `DEMO_MODE=true` показывает выбор ролей на странице входа; в обычной конфигурации он выключен. Авторизация выполняется в Keycloak.

## Резервное копирование и ошибки

Сохраняйте PostgreSQL и постоянные volumes для файлов и отчётов. При ошибках сначала проверьте `docker compose ps` и логи нужного сервиса; затем проверьте Keycloak, backend, frontend и статус миграций. API-документация доступна по `/docs` на адресе backend (обычно порт 8000). Не публикуйте `.env`, токены и резервные копии в CRM.
