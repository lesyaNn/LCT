# Контракты данных LMS и сайта

ТЗ «ИТ Школа Ростелекома» предусматривает интеграции, но не содержит адресов,
схем авторизации или форматов API заказчика. Ниже описан **внутренний контракт
CRM**, а не API Ростелекома. Реальный адаптер должен преобразовать ответ
провайдера в эти поля; URL, авторизация и правила опроса определяются после
получения контрактов заказчика.

## LMS → обучающиеся

`POST /api/v1/integrations/lms/ingest`, право `university.edit`, university
scope. Запрос:

```json
{
  "university_id": "00000000-0000-0000-0000-000000000001",
  "learners": [{
    "external_id": "lms-learner-42",
    "program_id": "00000000-0000-0000-0000-000000000002",
    "full_name": "Иван Иванов",
    "group_name": "Поток 1",
    "status": "active",
    "started_at": "2026-09-01",
    "progress": 42
  }]
}
```

`external_id` — стабильный ID в LMS, используется для идемпотентного upsert.
`program_id` — ID CRM, привязанный к указанному ВУЗу. Неизвестная связь не
создаётся по совпадению имени: запись учитывается как `unresolved`. Ответ
содержит `processed`, `unresolved`, `synced_at`. Допустимые статусы описаны в
Swagger. У строк сохраняются `source=lms` и `synced_at`.

## Сайт → заявки

`POST /api/v1/integrations/website/ingest`, то же право и scope:

```json
{
  "university_id": "00000000-0000-0000-0000-000000000001",
  "applications": [{
    "external_id": "website-application-42",
    "program_id": "00000000-0000-0000-0000-000000000002",
    "person_name": "Анна Иванова",
    "status": "new",
    "flow_name": "Поток 1",
    "external_created_at": "2026-09-20T12:00:00Z"
  }]
}
```

После приёма заявка доступна через
`GET /api/v1/universities/{university_id}/external-data?source=website`.
`POST /api/v1/workflow/instances/from-external` создаёт или связывает Workflow
по точному `external_id` и существующей связи ВУЗ–программа. Повторная
загрузка того же ID обновляет запись, не увеличивая счётчик заявок.

## Адаптеры и ошибки

`ExternalLmsAdapter` и `WebsiteAdapter` задают границу provider → CRM DTO.
Реальный провайдер должен вызывать удалённый API с ограниченным таймаутом
(контракт `timeout_seconds`, значение по умолчанию 10 секунд), преобразовывать
его ошибки в диагностируемый отказ синхронизации и затем вызывать ingest.
У текущего приложения нет адреса или учётных данных внешнего API; live pull
не настроен. `POST /api/v1/integrations/sync` работает только с
`EXTERNAL_ADAPTER_MODE=mock` вне production, иначе отвечает `503`.
Mock-адаптеры — **TEST/DEMO PROVIDER** со стабильными внешними ID, а не данные
заказчика. Тестовые обучающиеся помечены `source=mock_lms` и не отображаются
при отключённом mock-режиме. Доступность демо показывает
`GET /api/v1/integrations/capabilities`.

Батч ограничен 1000 элементами, а запись производится одной транзакцией.
Для подключения реального адаптера потребуются точные внешние контракты,
авторизация, политика повторов и таблица сопоставления идентификаторов программ.
