# Проверка ИИ-помощника

Повторная проверка на актуальном общем `main` описана в [отчёте переноса](ASSISTANT_MAIN_INTEGRATION.md). Ниже сохранены результаты первого прогона.

17.10.2026. База ветки: `main`, коммит `7cd7b95`.

Проверено на Ryzen 5 5625U, 8 ГБ RAM, без GPU. Python 3.12.14, PostgreSQL 16.15, Ollama 0.13.5. Рабочая модель: Qwen3 1.7B, поиск по смыслу: Qwen3 Embedding 0.6B. В базе знаний все 19 опубликованных пользовательских инструкций CRM, с разделением по ролям.

## Результат

* 68 тестов помощника и подготовки запуска прошли. Включены семь тестов настоящей PostgreSQL: миграции, хранение, права, конкурентная запись, удаление и срок хранения.
* Восемь сценариев API прошли с настоящими Ollama и PostgreSQL. Проверены возврат Workflow, отчёт, отсутствие вуза, dry-run, приглашение сотрудника, посторонний вопрос, просьба выполнить действие и запрос секретов.
* Девять проверок протокола прошли: 401 без входа, 403 для неизвестной роли, готовность хранилища, продолжение диалога, история, изоляция владельца и роли, 409 при устаревшей ревизии, удаление.
* Все 45 миграций применены на чистую тестовую базу; `migrate.py verify` вернул OK. Проверена установка backend в чистое окружение с закреплёнными зависимостями.

Полные синтетические ответы, источники и замеры: [assistant-acceptance.json](reports/assistant-acceptance.json). Вопросы проверялись через HTTP-контракт FastAPI и штатную проверку подписанных JWT. Для обнаружения ключа использован временный тестовый ключ, не живой сервер Keycloak. Это ограниченный приёмочный набор, не доказательство безошибочности любых ответов.

## Что исправлено

Ollama отвергала сгенерированную грамматику `char{1,4000}`. Ограничение длины перенесено из схемы генерации в проверку готового ответа; лимит токенов сохранён. Источники дополнительно ограничены перечислением разрешённых ID. Исправлена установка Python-пакета, добавлены проверка таблиц в readiness, повторное использование HTTP-соединений, быстрый путь FAQ и серверный отказ для явных команд изменения CRM или запроса секретов.

Qwen3 0.6B оказалась быстрее, но не прошла приёмку. Она не включена в подготовленные профили. 4B оставлена как настраиваемый вариант для более мощного стенда, без заявления о локальной проверке.

## Скорость и ограничения

Прогретые FAQ: около 0,05 с. Первый запрос без работающего Redis потратил около 4 с на переход к локальному ограничителю. Генерация и продолжение с 1.7B: примерно 18–23 с на этом CPU, включая поиск и сохранение. Обещания ответа за секунду для произвольного вопроса нет.

Compose-конфигурация проверена настоящим Docker Compose. Контейнерный стек здесь не запускался: Docker Engine отсутствует. Реальные модель и PostgreSQL были подняты отдельно. Frontend-виджет и выкладка на удалённый стенд не входят в эту проверку.

Общий набор без двух файлов с исходными ошибками сбора: 589 passed, 501 skipped, 5 failed. Пять падений повторяются на чистом `main`: локально нет жирного DejaVu Sans; в загрузке документа паспорта нет audit-контекста; workflow-мок и два теста списка вузов не учитывают `started_at`. Эти части не изменялись. Файлы `test_default_workflow_bootstrap.py` и `test_seed_demo.py` по-прежнему импортируют удалённые константы.

## Запуск на стенде

При работающем Docker Compose из корня репозитория:

```bash
python backend/scripts/start_assistant.py
```

Команда поднимает backend с зависимостями, скачивает недостающие модели, готовит индекс, прогревает генерацию и проверяет готовность. Скачивание не блокирует работу самой CRM. [Контракт API и параметры](ASSISTANT.md).
