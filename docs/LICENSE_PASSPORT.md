# Паспорт лицензии

Кнопка «Сформировать паспорт лицензии» находится на странице вуза во вкладке
«Лицензии», у каждой лицензии, включая мобильный вид. Workflow и его этапы
не участвуют в генерации. Функция доступна при реальном источнике данных и
праве `university.read`; backend дополнительно проверяет область доступа к вузу.

`GET /api/v1/universities/{university_id}/licenses/{license_id}/passport.pdf`
читает актуальные значения связанных записей одним SQL-запросом. Отсутствующие
поля и несогласованные связи возвращаются как `422` с
`error.details.missing_fields`. Требуются наименования вуза и ПО, номер лицензии,
связанный договор с номером и датой, даты начала и окончания лицензии.
При несоответствии вуза/продукта договора или обратном интервале дат документ
не формируется. Готовый PDF можно просмотреть, скачать и сформировать заново.
PDF не сохраняется как устаревающий серверный файл; ответ имеет `no-store`.

Макет использует существующий логотип ИТ Школы Ростелеком и цвета CRM.
Шрифт DejaVu Sans встраивается в PDF через общий механизм генерации отчётов.
Docker уже устанавливает `fonts-dejavu-core`; локально можно задать
`REPORT_PDF_FONT_DIR` (DejaVuSans.ttf и DejaVuSans-Bold.ttf).
Обычный документ занимает один A4. Предельно длинные названия и номера
переносятся на следующий лист с номером паспорта, QR и нумерацией страниц;
данные не обрезаются и не уменьшаются до нечитаемого размера.

## Проверка по QR

`FRONTEND_ORIGIN` должен указывать на реальный адрес CRM, доступный получателю
документа, например `https://crm.company.ru`. Ссылка не строится из HTTP Host.
QR содержит только `{FRONTEND_ORIGIN}/verify/license/{license_uuid}`.
Существующий `UUIDPKMixin` создаёт случайные UUID v4 (122 случайных бита).
Последовательные идентификаторы и UUID других версий для проверки не принимаются.
Новые поля, токены, секреты или миграции не требуются. Номер паспорта стабилен:
`LP-{license_uuid}`, дата формирования обновляется при каждом запросе.

Публичный `GET /api/v1/public/licenses/{license_id}/verification` доступен
без входа и возвращает только вуз, ПО, номер лицензии/договора, срок и статус.
Контакты, комментарии, файлы и идентификаторы пользователей не раскрываются.
Страница запрещена к индексации, ответы не кэшируются; повторная проверка и
возврат фокуса окна перечитывают сведения. При сетевой ошибке старая отметка
подтверждения скрывается.

Статус использует общие функции расчёта сроков лицензий и договоров:

- `confirmed`: сведения полны, договор подписан, даты начала наступили,
  сроки не истекли; последний день действия включён.
- `expired`: истёк срок лицензии или связанного договора.
- `revoked`: связанный договор имеет существующий статус `terminated`.
  Интерфейс поясняет «Договор прекращён». Отдельного поля отзыва лицензии
  в текущей модели нет, новый процесс отзыва не вводится.
- `invalid`: лицензия неизвестна/удалена, данные неполны или противоречивы,
  договор — черновик либо начало действия ещё не наступило.

Паспорт отражает статус на момент формирования (включая истёкшие лицензии).
QR проверяет текущую запись CRM, не является электронной подписью и не
удостоверяет неизменность содержимого PDF. Документ не заменяет договор.
Модель не содержит ИНН вуза и структурированных условий использования:
эти сведения не выдумываются, внутренние комментарии не публикуются.

## Проверки

```sh
cd backend
python -m pytest tests/test_license_passports.py -q
cd ../frontend
npm run typecheck
E2E_BASE_URL=http://localhost:3107 npx playwright test e2e/license-verification.spec.ts
```

API-тесты выполняют SQL в изолированной SQLite-базе и проверяют авторизацию,
границы доступа, неполные данные, актуальность повторной генерации, статусы,
ошибки PDF, A4, встроенную кириллицу, сохранение длинного текста и ссылку QR.
Browser-тесты используют контролируемые ответы API только в тестах и проверяют
публичный доступ, повторную проверку, ошибки и мобильную вёрстку.
