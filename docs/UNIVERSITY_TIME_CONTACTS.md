# Местное время и копирование

В паспорте вуза, рядом с городом и в разделе Ответственные, отображаются местные часы. Они обновляются раз в секунду и учитывают дату в городе вуза. Если время раньше 09:00 или начиная с 18:00, появляется подсказка. Это ориентир для звонка, а не расписание работы вуза.

У ответственного можно скопировать телефон, email или весь контакт с именем и должностью. Во вкладке Документы кнопка рядом с номером договора копирует только номер. Действия доступны читателю паспорта, дополнительных прав редактирования не требуют. Копирование выполняется только по нажатию, браузер показывает подтверждение или ошибку. Для Clipboard API нужен HTTPS либо localhost. При запрете доступа текст остаётся доступным для ручного копирования.

## JSON для фронтенда

`GET /api/v1/universities/{id}/passport` возвращает дополнительное поле:

```json
{
  "university": {
    "id": "7d0af272-c031-478a-83a4-5328c375ab43",
    "name": "Тестовый университет",
    "city": "Владивосток",
    "time_zone": "Asia/Vladivostok"
  }
}
```

Поле также есть в списке и деталях вузов. Оно вычисляется при чтении по городу и помечено `readOnly` в OpenAPI. Миграций и дополнительных запросов к базе нет. Новый backend совместим со старым frontend. Новый frontend принимает отсутствующее поле от старого backend и показывает, что местное время не определено.

Значение `null` означает неизвестный или неоднозначный город. Например, название Киров встречается в разных часовых поясах. Город не угадывается по части названия, московское время не подставляется. Строка с регионом или полным адресом требует отдельного разбора и в этой версии не распознаётся. Справочник ограничен населёнными пунктами России из исходной выгрузки; для зарубежных вузов зона не определяется.

## Справочник

Источник: [GeoNames cities500](https://download.geonames.org/export/dump/), актуальные русские имена из [alternate names RU](https://download.geonames.org/export/dump/alternatenames/RU.zip). Автор данных GeoNames, лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Использована производная выборка: населённые пункты RU, IANA-зоны и текущие русские названия; исторические названия исключены. Снимок от 17.10.2026, хеши исходников записаны в `backend/app/assets/city-time-zones.json`.

Справочник поставляется с backend. Во время работы сайт не отправляет город или контакты во внешние сервисы. Для обновления скачайте две исходные выгрузки и из каталога `backend` выполните:

```bash
python -m scripts.build_city_time_zones /path/cities500.zip --alternate-names /path/RU.zip --snapshot-date YYYY-MM-DD
```

После обновления пересоберите backend. JSON включён в package data и Docker-образ. Часовые правила для отображения времени берутся из Intl браузера, а не из фиксированного смещения UTC.

## Проверка реализации

Ветка `raisw-university-time-contacts`, основание `b808366`. Перед работой сделана локальная резервная копия. Миграций нет; после установки изменений нужно пересобрать backend и frontend.

Выполнены 85 серверных проверок: определение зон, нормализация города, неизвестные и неоднозначные названия, Калининград и Королёв, DTO, OpenAPI, API, старые mock-контракты и валидация форм. Все прошли. Это целевые проверки, не полный набор тестов проекта.

На frontend прошли четыре теста форматирования времени и контактов, TypeScript, ESLint изменённых компонентов и производственная сборка. Два сценария Playwright повторно прошли на готовой сборке: обновление часов и даты, копирование всех вариантов, мобильная ширина 390 px, отказ Clipboard API и неизвестный город. Проверено отсутствие изменяющих запросов к CRM при копировании. Авторизация и бизнес-ответы в этих браузерных сценариях имитируются; рабочая база не используется.

Из `backend`:

```bash
python -m pytest tests/test_city_time.py tests/test_service_api.py tests/test_p5_openapi_docs.py tests/test_p1_mocks.py tests/test_form_validation_schemas.py -q
```

Из `frontend`:

```bash
npm run test:university-time
npx playwright test e2e/university-time-contacts.spec.ts
```

Для Playwright требуется запущенный frontend с настоящим API-адаптером и Keycloak-режимом авторизации. Адрес можно задать через `E2E_BASE_URL`; обращения к API и OIDC перехватываются тестом.
