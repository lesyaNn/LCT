# Личные заметки

Раздел `/notes` доступен из бокового меню всем авторизованным пользователям.
Заметки принадлежат Keycloak `sub`: даже администратор не получает доступа
к чужим записям. Миграция `000050_personal_notes` применяется обычным SQL
мигратором при запуске backend.

При первом открытии раздела `POST /notes/initialize` создаёт личную заметку
«Заметки — мини-гайд» с примерами оформления, списками, задачами, цитатой,
кодом, таблицами, ссылками, командами и упоминанием своего профиля.
Миграция `000051_notes_onboarding` хранит отметку инициализации на сервере:
параллельные вкладки не создают дубликаты, изменения гайда не перезаписываются,
а после удаления он не восстанавливается. Гайд появляется и у пользователей,
у которых уже были заметки.

Заголовок и Markdown сохраняются через 650 мс после ввода. Каждый PATCH и
DELETE проверяет владельца и версию записи в SQL. При конфликте редактор
показывает серверную версию и предлагает сохранить свой текст отдельной
копией. При сетевой ошибке черновик остаётся в браузере с привязкой к
пользователю; сохранение повторяется через 5 секунд и при восстановлении
соединения. Неудачное создание можно безопасно повторить с тем же UUID.
Лимиты: 300 символов в заголовке, 200 000 символов Markdown.

При открытии раздела показывается сетка заметок. Выбор заметки открывает
редактор на всю ширину; кнопка «Все заметки» возвращает к сетке. Прямые
ссылки из глобального поиска по-прежнему открывают нужную заметку.

Редактор сразу показывает форматированный текст, который можно редактировать
на месте. Отдельных режимов просмотра и редактирования нет. Markdown-сочетания
при вводе превращаются в заголовки, выделение и списки; в API по-прежнему
хранится Markdown. Доступны Ctrl/⌘+B, I, K, Shift+S, Z и Shift+Z.
Меню `/` и поиск сущностей открываются рядом с курсором поверх страницы;
переключение команд и фокус поля поиска не прокручивают рабочую область.
Вместо общей команды `/entity` доступны отдельные пункты: «Вузы»,
«ИТ-направления», «ИТ-программы», «Вендоры», «ИТ-продукты»,
«Договоры и лицензии», «Ответственные». Договоры и лицензии ищутся вместе,
остальные пункты используют соответствующие каталоги CRM.

Рядом с «Удалить» находится кнопка «Экспорт» с меню PDF и Markdown. Markdown скачивается локально
в UTF-8 как `.md`, включая заголовок и текущий текст. PDF генерируется
авторизованным `POST /notes/export/pdf` из текущего документа редактора,
без необходимости сохранять или менять серверную заметку. PDF содержит
выделяемый текст с кириллицей, оформление, списки, задачи, таблицы и номера
страниц. CRM-ссылки разрешаются с правами текущего пользователя; изображения
представлены подписями и ссылками без загрузки внешних ресурсов.

Упоминание хранит тип, ID и при необходимости вуз в Markdown-ссылке.
При нажатии сервер повторно проверяет существование и область доступа.
Пользователи берутся из существующего Keycloak-сервиса: администраторы и
руководители видят разрешённую им выдачу, обычный пользователь может
упомянуть свой профиль. Остальные сущности используют существующие
справочники, глобальный поиск и university scope. Недоступные или удалённые
сущности не раскрываются. Сами заметки включены в `/api/v1/search` отдельной
группой и ищутся по исходному запросу, включая слова навигационных команд.

Проверки:

- Backend: `pytest tests/test_notes.py tests/test_global_search.py tests/test_p5_migrate_expected_guard.py`.
  Для интеграционных проверок задайте `TEST_DATABASE_URL`, указывающий на
  отдельную PostgreSQL-базу с `test` в имени: стандартная фикстура сбрасывает
  только эту тестовую схему и применяет SQL-миграции.
- Frontend: `npm run typecheck`, `npm run lint`, `npm run build`.
- Браузер: `npx playwright test e2e/notes.spec.ts`. Сценарий требует `E2E_NOTES_ISOLATED=1`,
  `E2E_BASE_URL`, `E2E_API_URL`, `E2E_ADMIN_USERNAME`, `E2E_ADMIN_PASSWORD`
  и отдельного стенда. Он проверяет форматирование, реальную ссылку на вуз,
  локальный и глобальный поиск, восстановление черновика после ошибки и
  перезагрузки, конфликт версий, удаление и мобильную ширину.
