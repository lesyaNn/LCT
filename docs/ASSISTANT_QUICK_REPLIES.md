# Быстрые ответы помощника

В чат добавлены 10 согласованных вопросов с готовыми ответами. В начале видны четыре кнопки, остальные открываются через Все быстрые вопросы. Под последним ответом доступна кнопка Ответ не подходит.

Список загружается с backend. Тексты ответов хранятся в `backend/app/modules/assistant/quick_replies.py` и опубликованы в Частых вопросах. Тест проверяет совпадение этих текстов. Frontend не подставляет ответ самостоятельно: отправляет вопрос и получает обычный JSON чата.

## API

`GET /api/v1/assistant/quick-replies` требует Keycloak JWT и право `assistant.use`. Модель, база данных и индекс документации для загрузки списка не нужны.

```json
{
  "version": "sha256-согласованных-текстов",
  "items": [
    {"id": "download-report", "question": "Как скачать отчёт?"},
    {"id": "explain-status", "question": "Что означает статус?"}
  ]
}
```

Показаны два элемента из десяти; фактическая version содержит 64 шестнадцатеричных символа. Для ответа используется существующий запрос:

```http
POST /api/v1/assistant/chat
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "message": "Что означает статус?",
  "conversation_id": "83666a9e-02e1-4bf5-894c-941471aeb1ea",
  "expected_revision": 1,
  "page": "reports"
}
```

Для нового диалога не передавайте conversation_id и expected_revision. Контракт запроса и ответа чата не менялся. Быстрый ответ имеет `model: null`, `retrieval_mode: lexical`; `knowledge_version` содержит SHA256 версии готовых текстов. Он сохраняется в личную историю вместе с вопросом и увеличивает revision.

Для вопроса о статусе сервер возвращает: Уточните, где вы видите статус: в Workflow, лицензии, договоре или отчёте. Напишите его название. Это уточнение с `basis: insufficient` и пустым `sources`, а не инструкция по отчётам. Та же логика действует после предыдущих вопросов. Ответ не подходит также получает согласованное уточнение. Остальные восемь ответов имеют `basis: documentation` и ссылку на Частые вопросы.

Сервер распознаёт точный текст кнопки и ограниченный перечень равнозначных фраз. Регистр, пробелы, ё/е и конечные знаки вопроса не важны. Например, Как выгрузить отчёт? работает как Как скачать отчёт?. Дополнительные условия не отбрасываются: Как скачать отчёт без прав администратора? обрабатывается обычным помощником, а не готовой инструкцией.

## Условия работы

Для отправки вопроса помощник должен быть включён через `ASSISTANT_ENABLED=true`, а PostgreSQL и таблицы диалогов доступны. Готовые ответы не требуют работающей Ollama или embedding-индекса и не занимают слот генерации. Значение ready в `/assistant/status` по-прежнему описывает готовность полной модели, оно не является условием получения готового ответа.

Проверки JWT, роли, владельца диалога, revision и лимит частоты запросов сохранены. Неверный владелец получает 404, устаревшая версия 409, превышение лимита 429. Выключенный помощник возвращает прежний `ASSISTANT_DISABLED` и для готового вопроса. Чужие сообщения не используются для подбора ответа.

При ошибке загрузки списка кнопок можно нажать Загрузить снова. Поле ручного ввода продолжает работать. При обновлении документов старый embedding-индекс автоматически перестаёт применяться до повторного индексирования; готовые ответы от этого не зависят.

Для установки пересоберите backend и frontend. Миграций нет.

## Проверки

На основании `bfd6432` выполнены 46 проверок готовых ответов и совместимости JSON: все 10 текстов для трёх ролей, работа при занятой модели, уточнения после отчёта, ограничения доступа, отсутствие запросов к модели и совпадение опубликованных текстов. Все прошли.

На отдельной PostgreSQL выполнены восемь интеграционных проверок истории: сохранение готовых ответов, загрузка после нового соединения, владелец, роль, revision и конкурентное сохранение. Все прошли; рабочие базы не использовались.

В Playwright прошли два браузерных сценария с ответами, сформированными текущим Python-сервисом без модели. Проверены последовательность отчёт → статус → Ответ не подходит, revision, восстановление истории, все 10 кнопок, мобильная ширина 390 px и повторная загрузка каталога. OIDC и HTTP в этих сценариях имитируются.

Производственная сборка Next.js, TypeScript, ESLint изменённых файлов и Ruff прошли. Оба браузерных сценария повторно выполнены на готовой сборке: 2 passed. Ветка реализации: `raisw-assistant-quick-replies`. Перед работой и отправкой выполняется локальное резервное копирование. Отдельная инструкция по ИИ для frontend сохранена без изменений.

В более широком серверном прогоне было 97 успешных проверок и семь падений. Те же семь падений воспроизведены на чистом исходном `bfd6432`: два старых ожидания прав руководителя и пять проверок OpenAPI из-за отсутствующих тегов у preview-маршрутов. Они не исправлялись в этой задаче. Полный набор тестов не объявляется зелёным.
