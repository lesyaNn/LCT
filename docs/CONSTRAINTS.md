# Условия и ограничения решения

Сводка того, в каких условиях стенд работает и чего он не умеет. Детали по
безопасности — в [SECURITY_ALIGNMENT.md](SECURITY_ALIGNMENT.md), по методам
обработки — в [DATA_PROCESSING.md](DATA_PROCESSING.md).

## Условия работы стенда

- Нужны Docker + Docker Compose v2, ~4 ГБ RAM, ~10 ГБ диска. Первый старт —
  до двух минут (Keycloak импортирует realm `rtk`, backend применяет миграции).
- Порты наружу: `3000` (CRM), `8000` (API/Swagger/ReDoc), `8081` (Keycloak).
  PostgreSQL и KeyDB наружу не публикуются — доступ через
  `docker compose exec`.
- Конфигурация — только через `.env` (шаблон `.env.example`). Значения
  `change-me` — только для локального запуска.
- Демо-учётные записи `admin/manager/user` — только локальный стенд.
- `docker compose down` сохраняет данные в томах; `docker compose down -v`
  удаляет базы, файлы и отчёты без восстановления.
- Повторный импорт realm пропускается (`Realm already exists`); полный сброс
  Keycloak — только через `down -v`.

## Функциональные ограничения

- Внешних LMS и сайта из коробки нет (`EXTERNAL_ADAPTER_MODE=disabled`).
  Для подключения нужны адреса, учётные данные и согласованные контракты API
  заказчика; ошибка реального API моками не подменяется.
- Seed создаёт демонстрационный срез (5 вузов, 1 шаблон Workflow на 5 этапов);
  полный маршрут на 14 этапов — отдельным скриптом
  `scripts/create_workflow_template.py`. Состав seed — в [DEMO_SEED.md](DEMO_SEED.md).
- Лимиты: вложения — `MAX_UPLOAD_MB=50` и фиксированный allowlist расширений;
  ingest-батч — до 1000 элементов в одной транзакции; health-score — батч
  до 50 вузов; фоновые задания — до 3 попыток, затем `failed`.
- Региональный scope менеджера не реализован; LOGIN/LOGOUT в аудите не
  фиксируются; антивирусное сканирование загрузок отсутствует.

## Безопасность и соответствие

- Это прототип: он **не сертифицирован ФСТЭК** и не является подтверждением
  соответствия 152-ФЗ. Таблица реализованных мер и gaps — в
  [SECURITY_ALIGNMENT.md](SECURITY_ALIGNMENT.md).
- Для промышленной эксплуатации обязательны: TLS, защищённое хранение
  секретов, резервное копирование с шифрованием и проверкой восстановления,
  модель угроз, firewall/IDS/IPS, SIEM, регламенты и обучение.
