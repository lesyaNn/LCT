# Условия и ограничения

## Запуск

Нужны Docker и Docker Compose v2. Первый запуск скачивает образы и зависимости. Для помощника отдельно скачиваются веса моделей. Фиксированное время старта и минимальный расход памяти для полного стенда не подтверждены нагрузочным измерением; они зависят от оборудования и включённых функций.

Наружу публикуются порты 3000, 8000 и 8081. PostgreSQL и Redis остаются во внутренней сети Compose.

Корневой `.env` задаёт подстановки Compose, но не передаётся всем контейнерам целиком. Изменяемый параметр должен присутствовать в `environment` или `build.args`. Публичные настройки frontend применяются при сборке.

Локальные пароли-примеры и Keycloak `start-dev` не являются конфигурацией промышленного стенда. Существующий realm не обновляется повторным импортом. Изменения его клиентов и пользователей выполняются отдельно; удалять все тома для этого не нужно.

## Данные и функции

Текущий seed добавляет пять вузов и связанные справочные данные. Шаблоны и экземпляры Workflow автоматически не создаются. Стандартный маршрут на 14 этапов устанавливается отдельной командой. [Демо-данные](DEMO_SEED.md).

Пользователь и руководитель видят назначенные вузы. Региональная область доступа руководителя сама по себе не вычисляется: нужны явные назначения. Карта использует доступные данные и сопоставление городов регионам, а не внешнюю геолокацию в реальном времени.

Модуль тендеров отсутствует. Внешние LMS и сайт по умолчанию выключены. Для реальной интеграции нужны адреса, учётные данные и согласованные контракты.

Вложения и Excel-импорт имеют разные ограничения форматов. `MAX_UPLOAD_MB` по умолчанию равен 50 для загрузок, использующих эту настройку. Excel-импорт отдельно ограничен 10 МиБ через `MAX_FILE_BYTES`. Изменение переменной в корневом `.env` без передачи её контейнеру не меняет настройку backend. Антивирусного сканирования загрузок нет.

Табличные отчёты поддерживают XLS, XLSX, PDF и JSON. Для фоновых операций нужен worker. Задания имеют ограниченное число повторов, после чего требуют разбора причины ошибки.

Личные заметки и диалоги помощника не доступны другому пользователю, включая администратора. Экспорт заметки или ответа не делает их общими внутри CRM.

## Дополнительные сервисы

Обычный Compose оставляет помощника выключенным. Локальная модель и индекс подключаются дополнительным файлом. Быстрые ответы не используют модель, но требуют включённого помощника и доступной базы диалогов. Генерация на CPU может занимать десятки секунд; скорость зависит от компьютера.

Документы базы знаний отбираются явно и ограничиваются правами. Помощник не читает весь репозиторий, не получает бизнес-данные вузов и не выполняет изменения CRM. Генеративные ответы могут содержать ошибки.

SMTP-сервера в поставке нет. Встроенное уведомление не гарантирует доставку письма. Настройки почты приложения не настраивают автоматически почту самого Keycloak.

`/health` и `/ready` проверяют ответ API-процесса, а не всю цепочку зависимостей. Worker, модель, SMTP, вход и операции с данными нужно проверять отдельно.

## Безопасность и эксплуатация

Это прототип без подтверждённой сертификации и без самостоятельного заключения о соответствии законодательству о персональных данных. Реализованные меры и известные пробелы перечислены в [SECURITY_ALIGNMENT.md](SECURITY_ALIGNMENT.md).

Для размещения за пределами локального компьютера отдельно настраиваются TLS, секреты, публичные адреса, правила сети, резервирование и проверка восстановления. Журнал бизнес-аудита не включает LOGIN и LOGOUT и не защищён криптографической цепочкой.

Резервировать нужно обе базы PostgreSQL и файловые тома. Git-копия не содержит данные БД, загрузки и веса. Обычный `docker compose down` сохраняет тома; флаг `-v` удаляет их и не нужен для обновления.

Результаты проверки исходников, ограничения проверки и найденные проблемы тестов находятся в [аудите проекта](PROJECT_AUDIT_2026-10-20.md).
